# HireMap Contributors

HireMap is built by people who contribute code, research, hiring knowledge, design, review, and lived experience.

Contributors are recognized based on the **quality, usefulness, and consistency** of their contributions rather than simply the number of commits or pull requests.

## Ways to contribute

### 🔎 Researcher

Improve the knowledge behind the map.

Examples:

* Research hiring processes and channels
* Add or verify sources
* Document organization-specific hiring patterns
* Identify differences between hiring routes
* Update outdated hiring information
* Contribute regional or industry-specific knowledge

### 🗺️ Map Contributor

Improve the hiring map and its underlying knowledge model.

Examples:

* Add organizations or organization types
* Add hiring channels and candidate entry points
* Create or improve hiring paths
* Add relationships between existing concepts
* Improve descriptions and examples
* Identify missing or unclear routes

### 🛠️ Developer

Improve the HireMap application.

Examples:

* Build new features
* Improve graph interaction and navigation
* Improve node and detail-panel components
* Improve accessibility and responsive behavior
* Improve performance
* Fix bugs
* Improve testing and developer tooling
* Improve documentation and contributor experience

A contribution can belong to more than one category.

---

## Contributor levels

Contributor levels describe a person's involvement in the HireMap community. They are **project recognition levels**, not automatic GitHub permission levels.

| Level                | Description                                                             |
| -------------------- | ----------------------------------------------------------------------- |
| 🌱 Contributor       | Has made an accepted contribution to the project                        |
| 🔎 Researcher        | Has made meaningful research, verification, or knowledge contributions  |
| 🗺️ Map Builder      | Has significantly improved hiring paths or map data                     |
| 🛠️ Core Contributor | Has made significant technical, structural, or cross-area contributions |
| ⭐ Maintainer         | Trusted contributor who helps review, maintain, and guide the project   |

Contributors may move between or hold multiple roles depending on the type of work they contribute.

There is no requirement to become a developer or maintainer to make valuable contributions.

---

## Recognition

Depending on their contribution and involvement, contributors may receive:

* Recognition on the project's contributor page
* Credits in project documentation
* GitHub acknowledgements
* Public recognition for significant contributions
* Recognition for specific research or map areas
* Opportunities to take ownership of project areas
* Core contributor or maintainer responsibilities for trusted contributors

Recognition is based on the impact and quality of the contribution, not activity volume.

---

## Maintainer roles

Maintainer status is separate from contributor recognition.

A contributor may be highly recognized without having write access to the repository.

Maintainers are trusted contributors who help with responsibilities such as:

* Reviewing pull requests
* Maintaining specific project areas
* Reviewing research and data quality
* Helping contributors
* Managing issues
* Improving project documentation
* Making or reviewing architectural decisions

Repository permissions are granted separately according to the responsibilities and trust required for the role.

### Typical progression

```text
Contribution
     ↓
Contributor
     ↓
Researcher / Map Builder / Developer
     ↓
Core Contributor
     ↓
Maintainer
```

This is not a mandatory progression. Someone can remain a contributor or specialist contributor without becoming a maintainer.

---

## Contributor credits

The project may maintain a public contributor list containing:

* GitHub username
* Contribution areas
* Notable contributions
* Contributor level or role
* Links to relevant work

The purpose is to give meaningful contributors visible credit for the work they have helped create.

---

## What makes a contribution meaningful?

HireMap prioritizes:

**Useful information over volume.**

Examples of meaningful contributions include:

* Adding reliable sources to an undocumented hiring route
* Correcting an inaccurate hiring process
* Mapping a previously missing organization type
* Improving the structure of the hiring knowledge model
* Building a reusable graph feature
* Improving accessibility or performance
* Reviewing and validating other contributions
* Documenting a hiring route based on relevant experience and evidence

A large number of small changes does not automatically result in a higher contributor level.

---

## Becoming a maintainer

Maintainer roles are invitation-based and are given to contributors who have demonstrated:

* Consistent contribution quality
* Good understanding of the project's goals
* Responsible handling of research and data
* Helpful collaboration with other contributors
* Ability to review and improve contributions
* Long-term interest in the project

Maintainer responsibilities and repository permissions may vary depending on the area of ownership.

---

## Recognition is part of the project

HireMap is intended to grow as a community-maintained knowledge map.

Whether someone contributes a single verified hiring route, researches an entire organization category, improves the graph, or helps maintain the project over time, their contribution should remain visible and attributable.
